# データスループット・アクセラレーター

ボトルネックが大量データの移動・変換・保存にある場合に、このスキルを使用する。目標は単なる速度ではない。目標は、より速く正確なデータを正しい場所へ届け、その証拠を残すことである。

## 最初の区別

最適化する前に以下を分離すること：

- ソース抽出速度；
- ネットワーク転送速度；
- ウェアハウスへの書き込み速度；
- 変換速度；
- サービングテーブルの鮮度；
- ジョブ実行中のライブテール増加。

パイプラインが「速い」としても、新しいデータが最終追い付きウィンドウより速く到着すれば、依然として遅れているように見える場合がある。

## 高速化のヒューリスティクス

- データがすでに存在する場所に計算を移動させる。
- 大きなランディングファイルには、ウェアハウスネイティブのスキャン、結合、追記を優先する。
- 完了済みのファイル/パーティションをスキップするために、マニフェストまたはチェックポイントを使用する。
- 読み取りと追記パターンに合ったパーティショニングおよびクラスタリングを使用する。
- 小さなファイル、リクエスト、書き込みをバッチ処理する。
- ユニークキー、マニフェスト、または置換可能なステージングによって書き込みをべき等にする。
- 生データ、派生データ、サービングテーブルを別々に管理する。

## ワークフロー

1. 現在のソース、ターゲット、マニフェストの契約を確認する。
2. バックログを計測する：外部ファイル、マニフェスト行、生データ行、派生行、最小/最大タイムスタンプ、未処理カウント。
3. 安全な追い付きまたはサンプルベンチマークを実行する。
4. バリアントを比較する：バッチサイズ、ワーカー数、ウェアハウスSQL、ファイルグルーピング、ステージング形式、マニフェスト更新方法。
5. カウントとタイムスタンプの整合性を保つ最速のパスのみを昇格させる。
6. そのパスをCLI、スケジュールジョブ、ワークフロー、またはランブックとして定式化する。
7. 定式化されたパスの実行後に最終集計を再実行する。

## 集計出力

以下のハード集計ブロックを使用する：

```text
Data throughput result:
- Source files discovered: 294
- Files processed this run: 294
- Raw rows added: 9,683,598
- Derived rows added: 8,917,585
- Remaining tail: 24 files at readback time
- Runtime: 38.7s
- Correctness gate: manifest counts and table max timestamps match
```

## ガードレール

- メトリクスをよく見せるために生データを削除しないこと。
- 失敗したファイルをサイレントにスキップしないこと。
- 過去のバックフィル状況とライブテールの鮮度を混同しないこと。
- ターゲットテーブルとマニフェストが一致するまでパイプラインを完了と呼ばないこと。
- 財務、医療、規制対象、または顧客影響のあるデータについては、リプレイ証拠と承認ゲートを保持すること。
