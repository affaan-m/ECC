# 再帰的意思決定台帳

ユーザーが繰り返しロールアウトや「Prime Gauss」スタイルの再帰プロンプトにより深い計算を強制しようとしている場合に、このスキルを使用する。有益な部分を保持する: 繰り返し試行、事前メモリ、新鮮な情報、明示的なマーク。危険な部分を除去する: ループが確実性を証明するという思い込み。

## 台帳の仕様

各ロールアウトでは以下を記録する:

- ロールアウト ID とタイムスタンプ;
- 前回の承認済みウィナーと前回のウォッチリスト;
- 取り込んだ新鮮な情報;
- 探索空間のサイズ;
- 使用したモデルファミリーまたはヒューリスティクス;
- 試行回数と有効試行回数;
- 上位候補;
- 意思決定マーク;
- 前の台帳に対するコヒーレンスマーク;
- プロモーションゲートの結果。

追記専用台帳には JSONL、人間向けサマリーには Markdown を推奨する。

## ロールアウトループ

1. 前の台帳を読み込む。
2. タイムステップゼロで新しい情報を取得する。
3. 境界付き探索を実行する。
4. 各候補にマークを付ける: 承認、監視、拒否、監視解除、または再試行が必要。
5. ウィナーを前のウィナーおよび最新のマーク済みロールアウトと比較する。
6. ドリフト、テールリスク、古いデータ、または失敗した再試行が前のマークを無効化した場合は候補をダウングレードする。
7. サマリーを作成する前にアーティファクトを追記する。

## コヒーレンスマーク

コンパクトなコヒーレンスマークを含める:

```text
Ensemble matches prior winner: true
Recursive matches prior winner: false
Latest rollout match: true
Live promotion allowed: false
Reason: replay and freshness gates not satisfied
```

## プロモーションルール

取引、資本配分、本番デプロイ、マイグレーション、または破壊的操作については、再帰的な確信は承認とはならない。

ユーザーがライブアクションを明示的に承認し、リポジトリ/サービスのゲートがそれをサポートしない限り、ペーパー、ドライラン、読み取り専用、プレビュー、またはステージングモードをデフォルトとする。

以下の条件がすべて満たされた場合のみプロモートする:

- 候補が選択した指標で前回の承認済みウィナーを上回っている;
- 正当性と再試行チェックが合格している;
- リスク制限が明示されている;
- 証拠が永続的である;
- 必要な場合にユーザーがライブステップを承認している。

## サマリーの形式

ドラマではなく意思決定を先頭に置く:

```text
Rollout 15 complete. The prior winner still holds, but edge deteriorated 17%.
Status: watch, not live. Next gate: 20 replay fills with fresh orderbook age
below threshold.
```
