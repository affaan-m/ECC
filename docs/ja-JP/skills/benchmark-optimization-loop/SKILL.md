# ベンチマーク最適化ループ

「20倍速くしたい」「50回の再帰的な最適化を試したい」といった要求を、実際にシステムを改善できる有界かつ計測可能なループへ変換するために、このスキルを使用する。

## 必須ベースライン

以下が揃うまで最適化を開始しないこと：

- 最適化対象の処理；
- 常にグリーンを保たなければならない正確性ゲート；
- 計測指標：ウォール時間、p95レイテンシ、行数/秒、コスト/実行、メモリ、エラー率；
- 現在のベースライン値；
- 探索予算：最大バリアント数、最大時間、最大コスト、最大データ影響範囲。

ユーザーが現実的でない目標を求めた場合でも、その意欲は尊重しつつ、ループを有界かつ計測可能に保つこと。

## ループ

1. ベースラインを計測する。
2. 証拠からボトルネックを特定する。
3. 仮説をそれぞれ1つ検証するバリアントを生成する。
4. 同じ入力形状でバリアントを実行する。
5. 正確性・安全性・再現性を満たさないバリアントを棄却する。
6. 最速の安全なバリアントを昇格させる。
7. 勝利したパスをスクリプト、コマンド、テスト、設定、またはドキュメントとして定式化する。
8. ベースラインと勝者を再実行してデルタを確認する。

## バリアント表

バリアントは以下のように追跡する：

```text
Variant | Hypothesis | Command | Time | Correct? | Notes
baseline | current path | npm run job | 120s | yes | stable
batch-500 | fewer round trips | npm run job -- --batch 500 | 42s | yes | winner
parallel-8 | more workers | npm run job -- --workers 8 | 31s | no | rate limited
```

## 再帰的探索

再帰的またはハイパーパラメータ探索の場合：

- すべての実行を台帳に永続化する；
- 直前の実行ではなく、直前に採用された勝者と比較する；
- ホールドアウトまたはリプレイチェックを維持する；
- 改善がノイズの範囲内に収まった場合、正確性が失敗した場合、コストが予算を超えた場合、または探索が説明可能な範囲を超えて変数を変更し始めた場合に停止する。

探索空間が実際に網羅的でない限り、「グローバル最適解」ではなく「計測された最良の安全なバリアント」という表現を使用すること。

## 昇格ゲート

バリアントが新しいデフォルトになるためには、以下をすべて満たす必要がある：

- 正確性テストが通過していること；
- パフォーマンスのデルタが繰り返し確認されているか説明されていること；
- ロールバックが明確であること；
- 変更がソース管理または恒久的なランブックに記録されていること；
- 最終サマリーに正確なコマンドと計測値が含まれていること。
