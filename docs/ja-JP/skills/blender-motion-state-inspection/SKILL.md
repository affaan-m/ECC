# Blender モーション状態インスペクション

## 使用するタイミング

- Blenderのキャラクターがアニメーション中にねじれ、左右反転、平坦化、オフセット、またはフットスライディングしているように見える場合。
- インポートされたアバター、アーマチュア、またはリターゲットされたモーションが期待するポーズと一致しているかどうかユーザーが確認したい場合。
- レンダリングされた証拠を、ボーン・バウンディングボックス・コンタクト・向きベクトルなどの構造化された事実と比較する必要がある場合。
- ワークフローがモデルをキャラクター、プロップ、プロキシメッシュ、コントロールリグ、または破損したインポートとして分類する必要がある場合。

## 基本原則

アニメーションされた3Dアセットをスクリーンショットだけで判断しないこと。スクリーンショットはレビューの証拠にはなるが、軸の慣例、ボーン名、オブジェクトスケール、ローカルトランスフォーム、親子関係のあるメッシュ、マテリアルスロット、フレームごとのコンタクト状態を隠してしまう。

まずBlenderの構造化された状態を抽出し、その後ビューポートのスクリーンショットやレンダーを使って事実が示す内容を確認する。

## 動作の仕組み

1. モーションを判断する前に、クリーンなシーンとアセットのベースラインを確立する。
2. エクスポーターまたはBlender自身のインタープリター内で実行されるBlender Pythonを使って、Blenderから構造化された事実を抽出する。
3. コンタクト、向き、スケール、リターゲティングのエラーが最も露出しやすいフレームをサンプリングする。
4. 計測された事実をユーザーの期待するポーズ、方向、グラウンドプレーン、レンダー目標と比較する。
5. 確認された事実、推定される原因、必要な修正を分けた簡潔なレポートを返す。

## インスペクションワークフロー

1. シーンのインベントリを作成する。
   - メッシュ、アーマチュア、エンプティ、カメラ、ライト、モディファイアー、親子関係、非表示オブジェクトを一覧化する。
   - アバターを判断する前に、キャラクターメッシュをヘルパー/プロキシジオメトリから分離する。
   - オブジェクト空間とワールド空間のバウンディングボックスを記録する。

2. スケルトンを特定する。
   - アーマチュア名、ポーズボーン、ボーンのヘッド/テール、ロール、親チェーン、コンストレイント、レストポーズの軸をキャプチャする。
   - 腰、脊椎、首、頭、肩、肘、手、太腿、膝、足首、足などのセマンティックボーンをマッピングする。
   - 左右のペアが欠けている場合や異常な命名規則にフラグを立てる。

3. 前後・上下・左右の軸を決定する。
   - 骨盤、脊椎、肩、腰、頭、足を合わせて使用する；単一のメッシュ法線に依存しないこと。
   - ローカルアーマチュアの軸とワールド軸、glTF Y-upとBlender Z-upなどのインポートファイル慣例を比較する。
   - 顔/頭/足の方向とルートモーションが矛盾する場合は、インポートが左右反転または逆向きである可能性をマークする。

4. アニメーションフレームをサンプリングする。
   - 最初、中間、コンタクト、空中、極端なフレームを検査する。
   - ルート位置、ルートの向き、骨盤の高さ、胴体の傾き、手足の方向、フットクリアランス、メッシュバウンドを記録する。
   - 長いまたは速いモーションの場合は、反転、着地、旋回、衝突、床コンタクトの周辺でより密にサンプリングする。

5. リターゲティングを責める前にモデルの整合性を確認する。
   - アニメーションを適用する前のクリーンなベースライン形状を確認する。
   - ユーザーが明示的に修正を求めない限り、元のメッシュ、マテリアル、アーマチュア、スキニングを保持する。
   - 説明のつかない球状のブロブ、巨大なプロキシメッシュ、または潰れたボディは、他に証明されるまでインポート/選択の問題として扱う。

6. コンタクトとモーションの問題を診断する。
   - 床への貫通：フレームごとに最も低い足またはシュー頂点と床の高さを比較する。
   - フットスライディング：接地フレームにわたって足のワールド位置を比較する。
   - 脚のクロスオーバー：左右の太腿、膝、足首、足の側面の順序を比較する。
   - ねじれのダメージ：ボーンのスウィング方向を手足の軸周りのロール/ねじれとは別に比較する。
   - スケールのドリフト：アニメーションされたメッシュバウンドをクリーンなベースラインバウンドと比較する。

7. 意見より事実を先に報告する。
   - フレーム番号、オブジェクト名、ボーン名、ワールド座標、閾値を含める。
   - 確認された失敗と視覚的な疑念を分けて記載する。
   - 構造化された状態が何を見るべきかを説明した後でのみ、スクリーンショットを添付する。

## 例

### フットスライディングのあるウォークサイクル

シナリオ：リターゲットされたキャラクターがウォークサイクル中にスケートしているように見えるが、正面カメラアングルでは足のコンタクトが判断しにくい。

ワークフローを適用する：
- シーンをインベントリする：キャラクターメッシュ `HeroBody`、アーマチュア `HeroRig`、グラウンドプレーン `Floor`、非表示のプロキシメッシュなし。
- スケルトンを特定する：セマンティックな足は `foot.L` と `foot.R`；腰は `pelvis`；ルートボーンは `root`。
- アニメーションフレームをサンプリングする：接地瞬間の前後のフレーム1、18、24、30、42、48を検査する。
- コンタクトとモーションの問題を診断する：接地フレームにわたって足のワールド空間位置を比較する。

抽出された事実：

| Frame | Fact | Evidence |
| --- | --- | --- |
| 18 | Left foot is planted | `foot.L min_z = 0.004`, toe and heel both near floor |
| 24 | Left foot slides while planted | `foot.L x = 0.21 -> 0.28` over six frames |
| 30 | Pelvis keeps moving forward | `pelvis y = 1.14 -> 1.31` |

判定：レンダー準備不足。モーションにフットロックのクリーンアップまたはリターゲティングコンストレイントのレビューが必要；ボディメッシュのプロポーション変更は不要。

### 逆向きにインポートされたキャラクター

シナリオ：静止フレームでは正常に見えるが、アニメーションが期待する移動方向とは逆に動く。

ワークフローを適用する：
- 前後・上下・左右の軸を決定する：頭、胸、足、ルートモーションを比較する。
- アニメーションフレームをサンプリングする：フレーム1と移動パスの中間点を検査する。
- 意見より事実を先に報告する：ルートの向きとモデルの正面方向を別々に含める。

抽出された事実：

| Frame | Fact | Evidence |
| --- | --- | --- |
| 1 | Character face points toward world `-Y` | head/chest vector from `neck` to `head` resolves to `-Y` |
| 72 | Root motion travels toward world `+Y` | `root y = 0.0 -> 2.8` |
| 72 | Feet remain visually forward-facing opposite travel | toe bones point `-Y` while displacement is `+Y` |

判定：インポートが逆向きであるか、リターゲティングの前後軸が一致していない可能性が高い。アニメーションカーブを編集する前に、インポート/リターゲットの軸マッピングを修正すること。

## 実用的な閾値

- シーンの単位スケールに別途記載がない限り、Blenderのデフォルトのメートルスケール単位を前提とする。
- 床がソフトまたは意図的にスタイライズされていない限り、1〜2 cmを超える床への貫通は視認可能として扱う。
- 5%を超える突然のスケール変化は、リグ、コンストレイント、またはトランスフォーム継承の問題として扱う。
- 空中での逆転モーション中に左右の足首の側面順序が入れ替わった場合、後で回復しても脚のクロスオーバーリスクとして扱う。
- ソースモーションにスナップターンが含まれていない限り、1フレームあたり30度を超えるルートの向きの急変は疑わしいと見なす。

## アンチパターン

- タスクが明示的にメッシュ修正でない限り、ポーズ一致を強制するためにボディのプロポーションを変更しないこと。
- クリーンなベースラインを記録する前にベイクしないこと。
- 1つのレンダリングカメラアングルをポーズが正しい証拠として使用しないこと。
- ヘルパーオブジェクトが何故キャラクターの一部でないかを記録する前に削除しないこと。
- 頭、足、胴体、ルートモーションを合わせて確認せずに、アバターが+Y、-Y、+X、または-Xを向いていると仮定しないこと。

## ツールに関する注記

Blenderの状態エクスポーターが利用可能な場合は、メッシュ、アーマチュア、ポーズボーン、マテリアル、コンタクト、バウンディングボックス、サンプリングされたアニメーションフレームを含むJSONを優先する。エクスポーターが存在しない場合は、`blender --background scene.blend --python collect_motion_state.py` のようにBlender自身を通じて小さなBlender Pythonスクリプトを実行すること。なぜなら `bpy` は通常のシステムPythonインタープリターでは利用できないためである。
