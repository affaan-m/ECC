# Itô Data Atlas エージェント

データソースを監視し、候補となる予測市場バスケットを構築し、パラメータ変更の草案を作成して、人間がレビューするためにその結果を渡すエージェントを設計するために、このスキルを使用する。

このスキルはアーキテクチャとワークフローを説明するものである。実際の取引は行わない。

## ガードレール

- すべての実行を明示的な人間の承認の後ろに置くこと。
- 別のプライベート実装が明示的に実行コントロールを追加していない限り、`ITO_API_KEY` はItôデータへの読み取り専用アクセスにのみ必要とすること。
- ターゲットリポジトリにすでにストレージ契約があり、ユーザーがそれを要求した場合を除き、プライベートなユーザーデータを永続化しないこと。
- プライベートな戦略ロジック、会場の認証情報、またはローカルパスを公開ドキュメントに公開しないこと。

## アーキテクチャパターン

4つのレーンを使用する：

1. リサーチコレクター：公開ウェブ、X、GitHub、会場ドキュメント、APIメタデータ、およびゲートアクセスが存在する場合はItôの読み取りエンドポイント。
2. バスケットドラフター：ソースを候補の原資産、ウェイト、ルール、および質問に変換する。
3. リスクレビュアー：データの鮮度、会場の制限、解決の曖昧さ、コンプライアンスノート、プロンプトインジェクションの露出を確認する。
4. 人間エディター：ユーザーが承認、拒否、調整、またはさらなる調査を依頼できるチャットまたはUI状態を開く。

## ワークフロー

1. ユーザーの目的と除外するアクションを定義する。
2. データソースとアクセス要件を一覧化する。
3. すべての原資産の出所を記載したバスケット仕様を草案する。
4. 実行可能な注文ではなく、編集可能なパラメータを作成する。
5. 監査証跡を保存する：入力、モデル出力、ソース、人間の判断。

## 有用なスキルチェーン

- `deep-research`：ソース収集に使用する。
- `x-api`：現在のソーシャル/イベントシグナルに使用する。
- `ito-market-intelligence`：会場と原資産のコンテキストに使用する。
- `ito-basket-compare`：ユーザーのナレッジベースとのマッチングに使用する。
- `prediction-market-risk-review`：実行可能なインテグレーションの前に使用する。

## 出力契約

以下を含む実装準備済みのワークフロー仕様を返すこと：

- データソース
- アクセスゲート
- エージェントの役割
- 人間の承認ポイント
- ストレージ/監査境界
- 非目標
