# 候補プレイブック: メンテナー所有の陳腐化 PR サルベージ

Candidate id: `maintainer-salvage-branch`

## 使用する場面

- 公開キューを維持可能な状態に保つため、陳腐化または競合した PR がクローズされた。
- クローズされた差分に、有用かつ焦点の絞られたアイデア・スキル・コマンド・ドキュメント・テスト・バグ修正が含まれている。
- コントリビューターがリベースする時間または意欲を持っていない可能性がある。

## 手順

1. ソース PR・作者・有用なコンセプト・クローズ理由を `docs/stale-pr-salvage-ledger.md` に記録する。
2. クローズされた PR の差分を現在の `main` と照らし合わせて再確認する。
3. パッチを安全にチェリーピックできるかどうかを判断する。現在のアーキテクチャが変化している場合は、再実装を優先する。
4. 焦点を絞った1つのサルベージ単位を持つ、メンテナー所有のブランチを作成する。
5. PR 本文に帰属情報を保持し、有用な場合はコミット本文にも記載する。
6. 変更したサーフェスに必要なカタログ・ドキュメント・テスト・リリース証拠を更新する。
7. 通常の変更と同じバリデーションゲートを実行する。
8. マージ後、台帳のステータスを pending/salvage-branch から landed・already-present・superseded・skipped・translator/manual review に更新する。

## 拒否条件

- パッチが大量生成された内容である。
- パッチが翻訳者/手動レビューを必要とする陳腐化したローカリゼーションである。
- パッチに個人パス・シークレット・ローカル設定・プライベートなオペレーターコンテキストが含まれている。
- パッチが現在のインストール・カタログ・プラグイン・リリースアーキテクチャを迂回している。
- 無関係なサルベージ単位が1つの PR に混在することになる。

## 最低限のバリデーション

- 変更したサーフェスを対象とした絞り込みテスト。
- `git diff --check`。
- ドキュメントを変更した場合は Markdown lint。
- スキル・エージェント・コマンド・プラグインサーフェスを変更した場合はカタログ/インストールのバリデーション。
