# AgentShield ポリシー例外プレイブック

Candidate id: `sarif-backed-timeboxed-exception-review`

AgentShield の組織ポリシー出力が、是正措置・期間限定例外・明示的な適用を必要とする検出結果を生成した場合に、このプレイブックを使用してください。

## 受け入れパス

1. AgentShield の検出結果 ID、カテゴリ、深刻度、影響を受けるファイルまたは MCP/フック サーフェス、ポリシーパックまたは組織ベースラインを特定する。
2. 判断を下す前にスキャナーの証拠を取得する:
   - SARIF/コードスキャン結果（特に `agentshield-policy/*`）
   - JSON/HTML レポートの証拠
   - ターミナルまたは GitHub Actions のジョブサマリーのカウント
3. 例外申請に必要なライフサイクルフィールドを記録する: 担当者、チケット、スコープ、有効期限、根拠、および状態（有効・まもなく失効・失効済み）。
4. 失効した例外は、新たな証拠が存在するまで拒否または適用されたままにしておく。
5. 即時の是正が可能かどうかを判断する。不可能な場合は、指定された担当者・チケット・スコープ・有効期限に紐付けた、範囲を絞った期間限定例外のみを昇格させる。
6. AgentShield のコード、ポリシーパック、適用設定、リリース状態、および稼働中のセキュリティ体制を、読み取り専用のエバリュエーター実行から除外する。

## 拒否パス

検出結果が不都合だからといって、ポリシーカテゴリ・ポリシーパック・組織ゲート全体を一括して抑制してはならない。

SARIF またはレポートの証拠、および現在の担当者・チケット・スコープ・有効期限なしに、クリティカル/高深刻度の検出結果をダウングレードしてはならない。

失効した例外を有効なものとして扱ってはならない。失効とは、メンテナーが新たな有界例外を作成するか根本的な問題を修正するまで、ポリシーゲートが引き続き適用されることを意味する。

## 最低限のバリデーション

- `npx ecc-agentshield scan --format json`
- AgentShield の SARIF/コードスキャン アーティファクトまたはレポートの証拠
- 経営レビューの証拠が必要な場合は `npx ecc-agentshield scan --format html`
- 現在の例外ライフサイクルフィールド: 担当者、チケット、スコープ、有効期限、ステータス
- `node tests/docs/evaluator-rag-prototype.test.js`
- `git diff --check`

スキャナーの証拠、ライフサイクルの状態、ポリシーパックのソース、および是正措置と例外の決定をメンテナーの PR 本文またはハンドオフに記録すること。
