# ECC для Codex

Локальный набор для Go, JavaScript/TypeScript, Rust 2024 и Zig.
16 самостоятельных скиллов: 14 в стандартной установке, PostgreSQL и Docker —
в опциональном профиле `infra`. Объёмные примеры хранятся в `references/`
и читаются по задаче, а не загружаются целиком.

## Установка

Нужны Python 3.9+ и POSIX shell. npm, дополнительные Python-пакеты и сеть
для установки не нужны.

Из корня этого репозитория:

```sh
./install.sh --list
./install.sh --dry-run
./install.sh
```

По умолчанию создаются ссылки `~/.agents/skills/ecc-*`. Это нативный
[пользовательский каталог скиллов Codex](https://learn.chatgpt.com/docs/build-skills).
Если новые скиллы не появились в списке, перезапусти Codex.

Только для конкретного проекта:

```sh
./install.sh --project /absolute/path/to/project
```

Выбор профилей заменяет стандартный набор; можно повторять `--profile`:

```sh
./install.sh --profile core --profile rust --profile zig
./install.sh --profile infra
./install.sh --profile all
```

Установка `infra` добавляет его к уже установленным скиллам. Установщик не
удаляет другие профили автоматически. Для собственного каталога обнаружения
или изолированной проверки есть `--dest /absolute/path/to/skills`.

Используются символьные ссылки: изменения этого checkout сразу доступны
Codex. Сохраняй его по тому же пути; перед перемещением или удалением выполни
удаление ссылок. Установщик отказывается перезаписывать конфликтующие файлы,
каталоги и чужие ссылки, включая сломанные, и проверяет весь план до записи.

Удаление всех ссылок этого checkout:

```sh
./install.sh --uninstall --profile all --dry-run
./install.sh --uninstall --profile all
```

Для проектной установки добавь тот же `--project`. Удаление затрагивает
только выбранные ссылки, которые всё ещё указывают на соответствующие
скиллы этого checkout. Глобальные `AGENTS.md`, `config.toml`, модели,
MCP-серверы и хуки установщик не меняет.

## Состав

| Профиль | Скиллы | По умолчанию |
| --- | --- | --- |
| `core` | `ecc-security`, `ecc-performance`, `ecc-verification` | Да |
| `go` | `ecc-go` | Да |
| `web` | `ecc-typescript`, `ecc-vue`, `ecc-react`, `ecc-node-backend`, `ecc-e2e`, `ecc-accessibility` | Да |
| `rust` | `ecc-rust`, `ecc-rust-unsafe`, `ecc-rust-navigation` | Да |
| `zig` | `ecc-zig` | Да |
| `infra` | `ecc-postgres`, `ecc-docker` | Нет |

Все имена имеют префикс `ecc-`, чтобы не пересекаться с другими наборами.
Скиллы доступны для автоматического выбора; их можно вызывать явно,
например `$ecc-rust`, `$ecc-go` или `$ecc-zig`.

Rust-материалы из `bol` объединены в три скилла. Сохранены темы ownership,
smart pointers, mutability, traits, типового проектирования, ошибок, async,
производительности, ресурсов и прикладных Rust-доменов. Удалены требования
несуществующих инструментов Claude Task/LSP, обязательные протоколы
«метапознания» и рекламные заставки. Unsafe-материалы проверены и переработаны.
Edition 2024 выбирается для новых проектов; существующие edition/MSRV и
зафиксированный toolchain сохраняются.

Убраны обвязка других агентов, старый npm-инсталлятор, переводы, команды,
автоматические хуки, дубликаты, прочие языковые наборы и неинженерные скиллы.
Источники и границы проверки перечислены в [SOURCES.md](SOURCES.md).

Из дополнительных тем имеет смысл оставить текущие PostgreSQL/Docker.
Следующим отдельным скиллом можно добавить Tauri v2 для связки Vue + Rust,
а Python — если регулярно нужны сетевые утилиты и автоматизация. В текущий
набор они не включены.

## Проверка набора

```sh
python3 -m unittest discover -s tests -v
python3 scripts/validate.py
sh -n install.sh
```

Тесты используют временные каталоги и изолированный `HOME`. Они проверяют
идемпотентность, dry-run, профили, конфликт до записи, сохранение чужих
файлов/ссылок, удаление собственных ссылок и откат при ошибке создания ссылки.
Валидатор проверяет каталог профилей, имена/описания и локальные Markdown-ссылки.
Это проверка упаковки и установщика, а не компиляция каждого примера из
всех языковых справочников.
