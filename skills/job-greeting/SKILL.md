# 岗位打招呼话生成

输入：**岗位 URL** + **候选人简历路径**，产出：**3 个版本**（复杂/中度/简单）可直接复制的打招呼话。

## 工作流

### 步骤 1：解析输入

- 岗位 URL（可能带 `securityId`、`_security_check` 等参数，保留完整 URL）
- 简历路径：支持 `.pdf`、`.md`、`.txt`
- 可选：`scripts/parse_job_url.py` 解析岗位平台与 job_id

### 步骤 2：读取岗位信息

**优先使用已配置的浏览器 MCP 抓取**（推荐 `graph-memory/browser-mcp`，其次 playwright MCP）：

1. 用 `browser_open` 打开岗位 URL
2. 检查返回的 `Title` 和 URL：
   - 若包含"招聘"或岗位名 → 进入岗位页，继续
   - 若跳转到登录/注册页（如 `web/user/?seed=` 或 `请稍候` / 验证页）→ **遇到反爬**，走下方反爬处理
3. 等待页面加载（SPA 需 5-10 秒），用 `browser_snapshot` 读取完整内容
   - **必须显式传 `tab_id`**（从 `browser_open` 返回结果中取），否则会报 "No active tab"
   - 快照中提取：岗位名、薪资、城市、经验/学历要求、任职要求、加分项、公司、对接人姓名

**反爬 / 登录墙处理**（BOSS 直聘等站点）：

- 无头模式常被重定向到登录页或"安全验证"页
- 若已配置 browser-mcp：切换到可见模式（`--no-headless`），提示用户用手机 APP 扫码登录一次，登录态会保存在 profile，之后自动读取
- 若无浏览器 MCP 或用户不便登录：**引导用户粘贴岗位描述文字**，走 `job-greeting-guided` 的逻辑
- 注意：BOSS 直聘的风控是 **IP 级别**，同一 IP 短时间内反复抓取会触发验证码，遇到时优先让用户粘贴文字而不是反复重试
- **持续无法获取时**（多次触发验证、被重定向、页面空白）：停止抓取，改用**截图 + 文字识别（OCR）**抽取岗位 JD——让用户在自己已登录的浏览器打开岗位页并截图，OCR 识别出 JD 文字，再交给本 skill 或 `job-greeting-guided` 处理

**成功抓取判定（每次抓取后务必确认）**：

| 标志 | 判定 | 处理 |
|---|---|---|
| Title 含"招聘"+岗位名，快照正文含"职位描述"/"任职要求"/"岗位职责" | ✅ **抓取成功** | 提取岗位信息，进入步骤 3 |
| URL 跳转到 `web/user/` 或 `web/passport/`，Title 含"登录/注册" | ❌ 未登录 | 走上方反爬处理（可见模式扫码 / 让用户粘贴文字） |
| Title 含"安全验证"/"请稍候" | ❌ 触发验证码 | 走反爬处理，**勿反复重试**（IP 风控会加剧） |
| 快照只返回导航栏/头部，正文无"职位描述" | ⚠️ 快照不完整 | 检查是否显式传 `tab_id`、等待 5-10 秒重试、或滚动后重读 |

> 未确认快照含"职位描述/任职要求"之前，不要开始匹配分析——否则会基于不完整岗位信息生成打招呼话。

### 步骤 3：提取简历文本

```bash
python3 <skill_dir>/scripts/extract_resume.py <简历路径>
```

脚本自动处理 PDF（PyMuPDF → pdftotext → pypdf），输出纯文本到 stdout。

### 步骤 4：匹配分析

构建「岗位要求 vs 简历优势」对照表：

- 从任职要求、加分项中提取 4-6 条硬性要求
- 在简历中找出对应的真实经历/技能作为证据
- 标注每条匹配的强弱；找出**明显短板**（如英语、特定行业经验）留作提醒，不在打招呼话中虚构

### 步骤 5：生成 3 个版本打招呼话

**先查风格偏好**（见【风格偏好记忆】）：
- 已有偏好 → 以该版本为主输出，同时附另外两版供备选
- 无偏好 → 直接输出完整 3 版，让用户挑选

三个版本定位：

| 版本 | 篇幅 | 特点 |
|---|---|---|
| **复杂版** | ~200 字 | 信息最全：1-2 个项目细节 + 完整技术栈 + 行业背景，适合中高端/技术深岗 |
| **中度版** | ~150 字 | 平衡：代表性项目 + 核心技术栈，通用首选 |
| **简单版** | ~100 字 | 精炼：一句话核心匹配 + 最亮眼的 1 个点，适合快速打招呼 |

产出后：
1. 三个版本分别标注【复杂版】【中度版】【简单版】，均为可直接复制的连续文本
2. **单独提醒**任何明显短板（如岗位要求英语而简历未体现）
3. 首次 / 用户提出调整时，询问用户偏好哪个版本，并把选择写入偏好记忆

## 风格偏好记忆

- 用户选定的版本偏好（复杂/中度/简单）持久化到 agent 偏好记忆：Claude Code 用 Claude 记忆（feedback 类型）；Codex 等其他运行时可写入项目内偏好文件（如 `.agents/prefs/job-greeting-style`），key 如 `job-greeting-style`
- 之后每次生成：先查记忆，有偏好就按该版本为主输出，**不再每次询问**
- 仅当用户明确说"调整风格 / 换个版本 / 换个风格"时，才重新输出 3 版并让用户挑选，随后更新记忆

## 生成规范

1. **称呼**：用岗位页上的对接人（如"古老师""赵女士"+其头衔）；未知则用"老师/您好"
2. **开门见山**：`{称呼}您好，看到您在招{岗位名}岗位。`
3. **正文**：突出 3 类信息，每条呼应岗位任职要求——
   - **项目经验**：1-2 个最有代表性的生产级项目
   - **开发能力**：语言、框架、工程能力
   - **大模型/核心技术栈**：LLM、Agent、RAG、微调、MCP 等（与岗位强相关的优先）
4. **去 AI 化**：不用"首先/其次/最后"或编号；不用工整排比；避免"高度契合/完美匹配"等空洞堆砌；口语自然，像真人打字
5. **格式**：一段连续文本，**不添加换行、不添加多余空格**，可直接复制到聊天框
6. **长度**：复杂 ~200 字 / 中度 ~150 字 / 简单 ~100 字
7. **结尾**：`简历已附上，期待与您进一步沟通，谢谢！` 或 `~`
8. **诚实**：只写简历中真实存在的内容；短板不在正文中虚构，另行提醒
